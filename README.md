# wasabi-hygiene

TOKYO WASABI の **衛生管理記録アプリ**（フロント側）。

いままで紙に書いていた「一般的衛生管理」「⑤ 重要管理のポイント」の記録を、
スマホから入力して Google スプレッドシートにためていきます。
保健所に出すときは、**紙とおなじ形の月次表**を印刷（PDF 保存）できます。

作りは **資材在庫アプリ（wasabi-inventory）と同じ**です。
画面は GitHub Pages、データは Apps Script（GAS）＋スプレッドシート。

| | URL |
|---|---|
| スタッフ用 | （公開したら書く）例：`https://momonewzealand.github.io/wasabi-hygiene/?site=ken` |
| 管理用（Momo 専用） | `…/wasabi-hygiene/admin.html` |
| 衛生管理計画 | `…/wasabi-hygiene/plan.html` |
| QRコード台紙 | `…/wasabi-hygiene/qr.html` |

管理用・QR台紙は、スタッフ用画面からリンクしていません。URL を知っている人だけが開けます。

---

## 記録する場所（拠点）

| 拠点 | URL の `?site=` | 沿っている衛生管理計画 |
|---|---|---|
| 工場 | `factory` | 漬物製造およびそうざい製造における衛生管理計画 |
| わさび食堂（牽引） | `ken` | 一般飲食店における衛生管理計画 |
| わさび食堂（自走） | `jiso` | 一般飲食店における衛生管理計画 |

「牽引 / 自走」の呼び方は、資材在庫アプリと合わせています。

## 準備（最初に1回だけ）

### 0. どこに置くか（先に決める）

**できれば共有ドライブの中に作ってください。** あとから移すより、最初からそこで作るほうが確実です。

| 置き場所 | 持ち主 | アカウントが使えなくなったら |
|---|---|---|
| 個人のマイドライブ | その個人 | **記録も一緒に失われる** |
| 共有ドライブ | 組織 | 記録は残る |

衛生記録が失われると「記録していない」のと同じ扱いになるので、ここは大事なところです。

注意が2つあります。

- **共有ドライブは Google Workspace の Business Standard 以上**でないと使えません。
  作成メニューに「共有ドライブ」が出てこなければ、プランが Business Starter の可能性があります。
  その場合は個人のマイドライブのままで構いませんが、**バックアップの持ち出し（後述）を必ずやってください**
- 健康状態（④-1）という個人情報が入るので、**衛生記録専用の共有ドライブを作ってメンバーを絞る**こと。
  大きい共有ドライブに入れると、そのメンバー全員が体調の記録を見られます

すでに作ったあとで移したくなった場合も、**ウェブアプリの URL は変わりません**
（スクリプトはスプレッドシートにくっついて一緒に移動します）。`ENDPOINT` を直す必要もありません。
移したあとは、**別のアカウントで開いて「記録」シートを直せないか一度試してください。**
共有ドライブは権限の考え方が変わるためです。
（2026年9月の導入時に確認したときは、共有ドライブでも保護は効いていました。
投稿者のメンバーは「記録」シートに入力できません）

### 1. スプレッドシートを作る

1. 上で決めた場所に、新しいスプレッドシートを作る（名前は「衛生記録」など）
2. **拡張機能 → Apps Script** を開く
3. 出てきたコードを全部消して、`gas/Code.gs` の中身を貼りつけて保存
4. 上の関数えらびで **`setup`** をえらんで実行
   - 初回は「承認が必要です」と出るので、自分の Google アカウントで許可する
   - 「準備ができました」と出れば成功
   - 「記録」「責任者確認」「設定」の3シートができ、前の2つは**手で書き換えられないよう保護**されます
5. 続けて **`setupBackupTrigger`** も実行する
   - 毎月1日の朝に、バックアップの CSV が Google ドライブの「衛生記録バックアップ」フォルダに書き出されます
6. **「設定」シート**で名簿を整える

   | 列 | 中身 |
   |---|---|
   | A | **記録者**（日々の記録をつける人）。初期値は もも / ひとし / たっちゃん |
   | B | 拠点（空欄なら全拠点で出てきます。`factory` `ken` `jiso` のどれか） |
   | C | **責任者**（月に1回まとめて確認する人）。初期値は ひとし / もも |

   記録者と責任者は**別の名簿**です。日々つける人と、それを見る人は役割が違うためです。

### 2. ウェブアプリとして公開する

1. Apps Script の右上 **デプロイ → 新しいデプロイ**
2. 種類は **ウェブアプリ**
3. 次のように設定して「デプロイ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. 出てきた **ウェブアプリの URL**（`https://script.google.com/macros/s/…/exec`）をコピー

> 「アクセスできるユーザー：全員」でないと、スタッフのスマホから使えません。
> Chrome の Google アカウント切り替えで開けなくなるのを避けるための作りです。

### 3. アプリに URL を教える

`common.js` の先頭にある `ENDPOINT` を、2 でコピーした URL に書き換える。

```js
const ENDPOINT = 'https://script.google.com/macros/s/AKfy…/exec';
```

**ここ1か所だけ**です。GAS を作り直して URL が変わったときも、ここを直します。

### 4. GitHub に上げて公開する

1. GitHub で `wasabi-hygiene` という**リポジトリ**（置き場）を作る
2. このフォルダの中身を push する
3. リポジトリの **Settings → Pages** で、公開するブランチを指定する
4. 1〜2分で `https://＜ユーザー名＞.github.io/wasabi-hygiene/` が開くようになる

以降は `git push` するだけで、1〜2分で公開サイトに反映されます。

### 5. QRコードを貼る

`qr.html` を開いて印刷すると、**A4 縦で3枚（拠点ごとに1枚）**出ます。
工場の入口、キッチンカー（牽引）の中、キッチンカー（自走）の中に貼ってください。
拠点ごとに中身の違うQRコードなので、貼り間違えないように気をつけてください。

紙には拠点名と「作業前と作業後に読みとってください」（キッチンカーは「営業前と営業後」）が
大きく入るので、貼るだけで使い方が分かるようにしてあります。

印刷するときの設定：

- **用紙**：A4・縦
- **余白**：デフォルト（四辺に 10mm ずつ白が残るよう、こちらで指定してあります）
- **ヘッダーとフッター**：オフにする。オンのままだと、URL や日付が余白に刷られて枠と重なります
- **倍率**：100%。「用紙に合わせる」で縮むと、QRも小さくなります

枠線を切り取ってラミネートすると、水まわりでも長持ちします。

## 使い方（スタッフ）

QRコードを読むと、その場所の画面がすぐ開きます。

1. **「営業前（作業前）の記録」** か **「営業後（作業後）の記録」** を押す
2. 項目ごとに **良 / 否** を押す。ふつうの日は上の **「すべて『良』にする」** を1回押せば済みます
3. **庫内温度**は数字を入れる。目安（冷蔵 5℃以下 / 冷凍 -15℃以下）を超えると赤くなり、対応を書く欄が開きます
4. **「否」を選ぶと、対応を書く欄が開きます**。ここは必ず書いてください（書かないと記録できません）
5. 名前を押して、**「記録する」**

ホームのいちばん下の「**衛生管理計画を見る**」から、計画書もその場で出せます。
保健所は「計画」と「記録」の両方を見るので、現場で聞かれたらここを見せてください。

### 記録するタイミングと項目

| | 工場 | わさび食堂（牽引 / 自走） |
|---|---|---|
| 作業前・営業前 | ① 原材料の受入 / ② 冷蔵庫・冷凍庫の温度 / ④-1 健康管理 / ④-2 手洗い | ① 原材料の受入 / ② 冷蔵庫の温度 / ④-1 健康管理 / ④-2 手洗い |
| 作業後・営業後 | ③-1 交差汚染 / ③-2 器具の洗浄 / ③-3 トイレ / 廃棄物 / 第1 非加熱 / 第3 加熱後、冷却 / 製造物 | ③-1 交差汚染 / ③-2 器具の洗浄 / 第1 非加熱 / 第2 加熱 / 第2 高温保管 |

項目と説明文は、保健所に出している衛生管理計画からそのまま写しています。

### 電波が届かないとき

キッチンカーは電波が弱い場所があります。
送信できなかった記録は**その端末に残り、電波が届いたときに自動で送られます**。
ホーム画面に「送信待ちが◯件あります」と出ている間は、
**そのスマホでアプリを開き直さないと送信されません**。
別の人のスマホからは送れないので、気づいたら開いてもらってください。

### 間違えたとき

記録は**あとから消せません**。間違えたら「訂正する」を押して、正しい内容で入れ直します。
元の記録もシートに残り、月次表には**訂正したほうが出ます**（特記事項に「訂正」と入ります）。

保健所に出す書類なので、あとから書き換えられない形にしてあります。

## 使い方（Momo・管理用）

`admin.html` を開きます。

- **拠点と年月をえらんで「表示」** … 紙とおなじ形の月次表が出ます
- **「責任者確認」** … 記録をひととおり見たら、責任者（ひとし / もも）をえらんで「確認した」を押す。
  手引書で「責任者は月に1回以上記録をチェックする」とされているので、**毎月必ず押してください**。
  押すと月次表の「確認者」欄と、印刷したときの下の確認欄に名前と日付が入ります
- **「印刷・PDF」** … そのまま印刷、または PDF で保存。A4 横2枚（一般的衛生管理／重要管理）
- **「CSV」** … 表計算ソフトで開ける形で保存。1行＝1回の記録で、訂正も全部そのまま入っています
- **「衛生管理計画」** … 計画書の画面へ。こちらも印刷できます

「否」や温度の目安超えは**赤いマス**になり、上に件数が出ます。
月の終わりにここを見れば、その月に何かあったかがひと目で分かります。

一度表示した月は端末に控えが残るので、**圏外でもすぐに出せます**
（「この端末の控えを出しています」と断りが出ます）。

## 手引書・法令まわりの確認結果

（公益社団法人日本食品衛生協会「HACCP の考え方に基づく衛生管理のための手引書（小規模な一般飲食店事業者向け）」に照らして）

### 記録の4点は必須にしてある

手引書で求められる **日付 / 項目ごとの良否 / 否のときの内容と対処 / 記録者** の4点は、
**入っていないと送信できません**。画面で止めるだけでなく、
GAS 側（`submitRecord`）でも同じ確認をしているので、画面を通さない送信でも入りません。

- 記録者は月次表の「**日々チェック**」欄に入ります
- 責任者の月1回の確認は「**確認者**」欄に入ります

### 保存期間

シートは**消す処理を一切持っていません**。記録は増えるだけです。
スプレッドシートの上限（1000万セル）に対し、1行あたり27列なので**約37万行**まで入ります。
3拠点×1日2回×365日 ＝ 年およそ2,200行なので、**100年以上たまっても足りなくなりません**。

法令で年数が決まっているわけではありませんが、自治体様式では「最後に記入してから1年以上」、
PL法の時効（3年）を考えると3年以上が安心、という見方があります。
**この作りなら消さずに残し続けられるので、3年でも10年でも問題ありません。**

### 改ざんされにくくしてある

- 記録は**追加だけ**。消す・書き換える処理がありません
- 時刻は**スマホの時計ではなく Google 側のサーバー**で打ちます（端末の時計をずらしても効きません）
- **未来の日付の記録は受け付けません**
- 訂正は元の記録を消さず、**新しい行として足します**（どちらもシートに残ります）
- 「記録」「責任者確認」シートは `setup()` で**保護**してあります。
  共有ドライブでも効くことを、別アカウントで実際に打ってみて確認ずみです
- スプレッドシートには Google の**変更履歴**も自動で残ります（ファイル → 変更履歴）

> ただし、**シートの持ち主（Momo）だけは手で直せます**。ここは仕組みでは防げないので、
> 「記録は直さない。直すならアプリの訂正から」という運用で守ってください。

### 衛生管理計画との一致

`plan.html`（計画書の画面）と記録フォームは、**`common.js` の同じ定義から作られています**。
片方だけ直すことができないので、計画と記録項目がズレません。

計画を変えたときは、`common.js` の `ITEMS` を直せば、
計画書の画面も記録フォームも月次表も、まとめて変わります。

### すぐに提示できる

- 記録 … 一度表示した月は端末に残るので、圏外でもすぐ出せます
- 計画 … `plan.html` の中身は `common.js` に入っているので、圏外でも開けます
- どちらも**印刷・PDF 保存**ができます

**運用の助けとして、月に1回 PDF にして保存しておく**と、万一アプリが開けないときも出せます。

### バックアップ

- 毎月1日の朝、`backup()` が **CSV を「衛生記録バックアップ」フォルダ**に書き出します
  （`setupBackupTrigger` を1回実行しておくこと）
- このフォルダは**スプレッドシートと同じ場所**に作られます。
  共有ドライブに置いていれば、バックアップも共有ドライブの中に入ります
  （2026年9月の導入時に、共有ドライブで実際にそうなることを確認ずみ）
- CSV なので、将来この仕組みをやめても中身を読めます
- **四半期に1回は、その CSV を OneDrive かパソコンにも落としてください。**
  Google アカウントごと使えなくなると、ドライブの中のバックアップも一緒に失われるためです
- スプレッドシートは、**Momo 以外にもう1人**、閲覧できる人を付けておくと安心です

## 直したいとき

### 記録する人・責任者を増やす、減らす

スプレッドシートの **「設定」シート**を直すだけ。アプリ側は何もしなくていいです。

- **A 列** … 記録者（スタッフ画面の「記録した人」に出てくる）
- **C 列** … 責任者（管理画面の「責任者をえらぶ」に出てくる）

いまは責任者を **ひとし / もも** の2人にしてあります。増やしたければ C 列に足してください。

### 記録する項目を増やす・減らす（衛生管理計画を変えたとき）

**2か所**を直します。

1. `common.js` の `ITEMS`（画面・計画書・月次表に出る項目）
2. `gas/Code.gs` の `COLUMNS`（シートの列）に、同じ `id` の行を足す

足したあと、Apps Script で **`setup` をもう一度実行**すると見出しが直ります。
すでにある記録は消えません。

### 合言葉をかける（いまはかけていません）

いまは「URL を知っていれば誰でも記録・閲覧できる」設定です。
制限したくなったら、**同じ文字**を次の2か所に入れます。

1. `common.js` の `ACCESS_KEY`
2. `gas/Code.gs` の `ACCESS_KEY`（直したら、Apps Script で「デプロイを管理 → 編集 → 新バージョン」で入れ直す）

QRコードは作り直さなくて大丈夫です（合言葉はアプリの中に入っているため）。

### アド弁について

青梅駅での販売時に作った「⑤ 重要管理のポイント【アド弁】」は、
**現在使っていないため、アプリの項目からは外してあります。**

> 保健所に出している衛生管理計画にアド弁の欄が残っている場合、
> 計画書とアプリの内容が食い違います。**計画書側も「休止」または削除**にそろえてください。
> 立ち売りを再開するときは、`common.js` の `ITEMS` と `gas/Code.gs` の `COLUMNS` に
> `adoben`（アド弁の輸送・販売）を足せば戻せます。

## 気をつけること

### 従業員の健康状態は個人情報

「④-1 健康管理：否」と記録者名が並ぶと、体調の記録そのものになります。
**スプレッドシートは非公開のまま、見られる人を限る**運用にしてください。
画面（GitHub Pages）側には名簿しか置いていないので、記録の中身が公開されることはありません。

### リポジトリは Public、GAS の URL も公開される

GitHub Pages を無料で使うためリポジトリは Public です。
資材在庫アプリと同じく、**GAS の URL がソースの中に見える**状態になります。
いたずら書き込みの被害が出たら、GAS を**新しいデプロイで作り直して URL を差し替える**（`common.js` の `ENDPOINT` 1か所）ことで止められます。
記録は追加しかできない作りなので、既存の記録が消されることはありません。

### 保健所への確認

HACCP の記録は電子でも認められていますが、提出・提示のときの運用は保健所ごとに違うことがあります。
**東京都西多摩保健所（0428-22-6141）**に、

- 記録をアプリで取り、必要なときに印刷して出す形で問題ないか
- 記録の保存期間は何年か

を一度確認しておくと安心です。
